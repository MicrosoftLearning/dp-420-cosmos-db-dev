In this exercise, you set up an Azure Cosmos DB SDK project, connect to the local emulator, validate the connection, add a logging handler to observe SDK traffic, and then switch to a cloud account using environment variables.

## Before you start

To complete this exercise, you need an [Azure subscription](https://azure.microsoft.com/free/) with permission to create resources and assign roles.

If your lab environment isn't set up yet, follow [Set up your lab environment](https://github.com/MicrosoftLearning/dp-420-cosmos-db-dev/blob/main/Allfiles/Labs/Shared/00-setup-local-environment.md) to install Visual Studio Code, Git, the Azure CLI, and PowerShell 7.

You also need the **Azure Cosmos DB emulator** running locally. See [Use the Azure Cosmos DB emulator for local development](/azure/cosmos-db/emulator) for setup instructions.

::: zone pivot="csharp"

You also need the [.NET 10 SDK](https://dotnet.microsoft.com/download) or later installed.

::: zone-end

::: zone pivot="python"

You also need [Python](https://www.python.org/downloads/) 3.12 or 3.13 installed.

::: zone-end

## Set up your Azure Cosmos DB resources

Most of this exercise runs against the local emulator. The final task switches to a cloud account, which this learning path shares across its exercises. If your account, database, and containers are already set up, skip ahead to the next section and reuse them.

If they aren't set up yet, run the shared setup script now.

1. Start **Visual Studio Code**.

1. If you haven't already cloned the lab code repository for **DP-420**, open the command palette with **Ctrl+Shift+P** and run **Git: Clone** to clone `https://github.com/microsoftlearning/dp-420-cosmos-db-dev` into a local folder of your choice. Otherwise, open the folder you cloned previously.

1. Once the repository is cloned, open that local folder in **Visual Studio Code**.

1. In the **Explorer** pane, browse to the **Allfiles/Labs/Shared** folder.

1. Open the context menu for the folder and select **Open in Integrated Terminal**. If the terminal isn't PowerShell, select the dropdown beside the **+** in the terminal toolbar and choose **PowerShell**.

1. Sign in to the Azure CLI. A browser window opens so you can sign in to Azure.

    ```azurecli
    az login
    ```

1. Set variables for the resource group (If a resource group was provided by your lab environment, use that name) and region you want to use. Change either value if you prefer a different resource group name or region.

    ```powershell
    $resourceGroup = "dp420"
    $location = "westus2"
    ```

1. Run the setup script.

    ```powershell
    ./setup.ps1 -ResourceGroup $resourceGroup -Location $location -NamePrefix dp420lab03
    ```

    Azure Cosmos DB account names have to be globally unique, so the script builds one for you by adding six random characters to the prefix, giving a name like `dp420lab03a7f3k9`.

1. Wait for the script to finish. The whole script takes 5-10 minutes to run.

1. Record the **Account name** and **Account endpoint** values the script prints. You need the endpoint in the final task, and it looks like `https://<your-account-name>.documents.azure.com:443/`.

The script creates the following resources:

| Resource | Configuration |
| :--- | :--- |
| Azure Cosmos DB account | API for NoSQL, with key-based authentication disabled |
| `cosmicworks` database | Holds every container this learning path uses |
| `product` container | Partitioned on `/categoryId`, autoscale up to 1000 RU/s, loaded with 295 CosmicWorks products |
| Role assignment | Cosmos DB Built-in Data Contributor, granted to your signed-in identity |

Because key-based authentication is disabled, no key or connection string appears anywhere in this exercise. Every operation against the cloud account authenticates with the identity from your `az login` session, which is the recommended approach for new accounts.

> [!NOTE]
> A new role assignment takes a few minutes to propagate. If a later step fails with a 403 error, wait a moment and try again.

## Task 2: Connect to the emulator and read account properties

The emulator uses a well-known fixed endpoint and key. Start by pointing the SDK at the emulator and calling `ReadAccountAsync` to verify the connection succeeds.

::: zone pivot="csharp"

1. In **Program.cs**, below the using directives, add the emulator connection constants and client initialization:

    ```csharp
    string endpoint = "https://localhost:8081/";
    string key = "C2y6yDjf5/R+ob0N8A7Cgv30VRDJIWEHLM+4QDU5DE2nQ9nDuVTqobD4b8mGGyPMbIZnqyMsEcaGQy67XIw/Jw==";

    CosmosClientOptions options = new()
    {
        HttpClientFactory = () =>
        {
            var handler = new System.Net.Http.HttpClientHandler
            {
                ServerCertificateCustomValidationCallback =
                    System.Net.Http.HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
            };
            return new System.Net.Http.HttpClient(handler);
        },
        ConnectionMode = ConnectionMode.Gateway
    };

    CosmosClient client = new(endpoint, key, options);
    ```

    > [!WARNING]
    > `DangerousAcceptAnyServerCertificateValidator` disables SSL certificate validation. Use this only for the local emulator; never use it in production code. Alternatively, import the emulator certificate as described in [Import the emulator's TLS/SSL certificate](/azure/cosmos-db/how-to-develop-emulator#import-the-emulators-tlsssl-certificate) and omit the custom `HttpClientFactory`.

1. Read account properties to verify the connection:

    ```csharp
    AccountProperties account = await client.ReadAccountAsync();
    Console.WriteLine($"Account name:     {account.Id}");
    Console.WriteLine($"Primary region:   {account.WritableRegions.FirstOrDefault()?.Name}");
    Console.WriteLine($"Consistency:      {account.Consistency.DefaultConsistencyLevel}");
    ```

1. Run the project:

    ```bash
    dotnet run
    ```

1. Verify that the output shows the emulator account name (typically **localhost**), the primary region, and the consistency level.

::: zone-end

::: zone pivot="python"

1. In **app.py**, below the imports, add the emulator connection constants and client initialization:

    ```python
    endpoint = "https://localhost:8081/"
    key = "C2y6yDjf5/R+ob0N8A7Cgv30VRDJIWEHLM+4QDU5DE2nQ9nDuVTqobD4b8mGGyPMbIZnqyMsEcaGQy67XIw/Jw=="

    # connection_verify=False bypasses SSL validation for the local emulator only
    client = CosmosClient(url=endpoint, credential=key, connection_verify=False)
    ```

    > [!WARNING]
    > `connection_verify=False` disables SSL certificate validation. Use this only for the local emulator; never use it in production code. Alternatively, import the emulator certificate and remove this parameter.

1. Read account properties to verify the connection:

    ```python
    def main():
        account = client.get_database_account()
        # DatabaseAccount exposes PascalCase attributes
        print(f"Account endpoint: {endpoint}")
        print(f"Consistency:      {account.ConsistencyPolicy}")

    main()
    ```

1. Run the script:

    ```bash
    python app.py
    ```

1. Verify that the output shows the emulator endpoint and the default consistency policy.

::: zone-end

## Task 3: Create a database and container

With the connection verified, create the `cosmicworks` database and `product` container on the emulator.

The emulator authenticates with a key, which carries both data-plane and control-plane rights, so the SDK can create these resources. Task 6 revisits this point, because the same code can't run against a cloud account that authenticates with Microsoft Entra ID.

::: zone pivot="csharp"

1. Below the account output, add the following code to create the database and container:

    ```csharp
    Database database = await client.CreateDatabaseIfNotExistsAsync("cosmicworks");
    Console.WriteLine($"Database:         {database.Id}");

    Container container = await database.CreateContainerIfNotExistsAsync(
        id: "product",
        partitionKeyPath: "/categoryId",
        throughput: 400);
    Console.WriteLine($"Container:        {container.Id}");
    ```

1. Run the project again and confirm both names appear in the output.

::: zone-end

::: zone pivot="python"

1. Inside the `main` function, below the account output, add the following code:

    ```python
    database = client.create_database_if_not_exists(id="cosmicworks")
    print(f"Database:         {database.id}")

    container = database.create_container_if_not_exists(
        id="product",
        partition_key=PartitionKey(path="/categoryId"),
        offer_throughput=400
    )
    print(f"Container:        {container.id}")
    ```

1. Run the script again and confirm both names appear in the output.

## Task 4: Add a logging handler

Add a logging handler so you can see the HTTP method, URI, status code, and request-unit charge for every SDK request.

::: zone pivot="csharp"

1. At the **bottom** of **Program.cs**, after all top-level statements, add the following class definition:

    ```csharp
    public class LogHandler : RequestHandler
    {
        public override async Task<ResponseMessage> SendAsync(
            RequestMessage request, CancellationToken cancellationToken)
        {
            Console.WriteLine($"  [REQ]  {request.Method.Method} {request.RequestUri}");
            ResponseMessage response = await base.SendAsync(request, cancellationToken);
            Console.WriteLine($"  [RES]  {(int)response.StatusCode} {response.StatusCode}" +
                              $"  RU: {response.Headers.RequestCharge:0.00}");
            return response;
        }
    }
    ```

1. Remove the `CosmosClientOptions options` block you added in Task 2, then replace the `new CosmosClient(endpoint, key, options)` line with a builder-based client that registers the handler. The builder's fluent methods cover both settings the options object held:

    ```csharp
    CosmosClient client = new CosmosClientBuilder(endpoint, key)
        .WithConnectionModeGateway()
        .WithHttpClientFactory(() =>
        {
            var handler = new System.Net.Http.HttpClientHandler
            {
                ServerCertificateCustomValidationCallback =
                    System.Net.Http.HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
            };
            return new System.Net.Http.HttpClient(handler);
        })
        .AddCustomHandlers(new LogHandler())
        .Build();
    ```

    > [!NOTE]
    > `CosmosClientBuilder` is in the `Microsoft.Azure.Cosmos.Fluent` namespace, which is already included in the using directives you added in Task 1.

1. Run the project again. Each SDK request now logs its HTTP method, URI, status code, and RU charge to the console.

::: zone-end

::: zone pivot="python"

1. Below the imports and before the `main()` call, configure the `azure.cosmos` logger to `DEBUG`:

    ```python
    logging.basicConfig(
        stream=sys.stdout,
        level=logging.DEBUG,
        format="%(asctime)s %(name)s %(levelname)s %(message)s"
    )
    logging.getLogger("azure.cosmos").setLevel(logging.DEBUG)
    ```

1. Run the script again. The console now shows the HTTP requests the SDK makes, including URIs, status codes, and headers.

    > [!TIP]
    > In production, use `logging.WARNING` or `logging.INFO` to reduce verbosity. `logging.DEBUG` is valuable for diagnosing individual operations during development.

::: zone-end

## Task 5: Handle a simulated connection error

Attempt to read an item that does not exist and inspect the resulting exception, confirming you can distinguish transient errors (worth retrying) from permanent errors (that require a code fix).

::: zone pivot="csharp"

1. Below the container creation code, add a `try/catch` block that attempts to read a nonexistent item:

    ```csharp
    try
    {
        var response = await container.ReadItemAsync<dynamic>(
            id: "nonexistent-id",
            partitionKey: new PartitionKey("nonexistent-category"));
    }
    catch (CosmosException ex)
    {
        Console.WriteLine($"\nCaught CosmosException:");
        Console.WriteLine($"  Status code:    {(int)ex.StatusCode} ({ex.StatusCode})");
        Console.WriteLine($"  Is retryable:   " +
            $"{ex.StatusCode == System.Net.HttpStatusCode.TooManyRequests ||
               ex.StatusCode == System.Net.HttpStatusCode.ServiceUnavailable}");
    }
    ```

1. Run the project. The output shows a **404 Not Found** exception. Observe that `Is retryable` prints `False`: a 404 means the item does not exist and retrying does not help. This is the basis of the write-retry pattern covered in the error-handling unit.

::: zone-end

::: zone pivot="python"

1. Below the container creation code, add a `try/except` block that attempts to read a nonexistent item:

    ```python
    try:
        container.read_item(
            item="nonexistent-id",
            partition_key="nonexistent-category"
        )
    except exceptions.CosmosResourceNotFoundError as ex:
        print(f"\nCaught CosmosResourceNotFoundError:")
        print(f"  Status code:    {ex.status_code}")
        print(f"  Is retryable:   {ex.status_code in (429, 503)}")
    except exceptions.CosmosHttpResponseError as ex:
        print(f"\nCaught CosmosHttpResponseError:")
        print(f"  Status code:    {ex.status_code}")
        print(f"  Is retryable:   {ex.status_code in (429, 503)}")
    ```

1. Run the script. The output shows a **404 Not Found** error. `Is retryable` prints `False`: a missing resource requires a code fix, not a retry.

::: zone-end

## Task 6: Switch to a cloud account

Change the client to target an Azure Cosmos DB cloud account by setting environment variables, without modifying any application code.

The cloud account authenticates with Microsoft Entra ID, and a Cosmos DB data-plane role grants no control-plane rights. Creating a database or container is a control-plane operation, so the creation code from Task 3 returns a 403 error against the cloud account no matter which data-plane role you hold. The setup script already created those resources, so the cloud path reads them instead.

::: zone pivot="csharp"

1. Replace the hardcoded emulator constants with environment variable lookups:

    ```csharp
    string? rawEndpoint = Environment.GetEnvironmentVariable("COSMOS_ENDPOINT");
    bool useCloud = rawEndpoint != null;
    string endpoint = rawEndpoint ?? "https://localhost:8081/";
    string emulatorKey = "C2y6yDjf5/R+ob0N8A7Cgv30VRDJIWEHLM+4QDU5DE2nQ9nDuVTqobD4b8mGGyPMbIZnqyMsEcaGQy67XIw/Jw==";
    ```

1. Replace the client creation block with:

    ```csharp
    CosmosClient client;

    if (useCloud)
    {
        client = new CosmosClientBuilder(endpoint, new DefaultAzureCredential())
            .AddCustomHandlers(new LogHandler())
            .Build();
    }
    else
    {
        client = new CosmosClientBuilder(endpoint, emulatorKey)
            .WithConnectionModeGateway()
            .WithHttpClientFactory(() =>
            {
                var handler = new System.Net.Http.HttpClientHandler
                {
                    ServerCertificateCustomValidationCallback =
                        System.Net.Http.HttpClientHandler.DangerousAcceptAnyServerCertificateValidator
                };
                return new System.Net.Http.HttpClient(handler);
            })
            .AddCustomHandlers(new LogHandler())
            .Build();
    }
    ```

1. Replace the database and container creation from Task 3 so that it only runs against the emulator:

    ```csharp
    Database database;
    Container container;

    if (useCloud)
    {
        database = client.GetDatabase("cosmicworks");
        container = client.GetContainer("cosmicworks", "product");
    }
    else
    {
        database = await client.CreateDatabaseIfNotExistsAsync("cosmicworks");
        container = await database.CreateContainerIfNotExistsAsync(
            id: "product",
            partitionKeyPath: "/categoryId",
            throughput: 400);
    }

    Console.WriteLine($"Database:         {database.Id}");
    Console.WriteLine($"Container:        {container.Id}");
    ```

    `GetDatabase` and `GetContainer` build a client-side reference without calling the service, so neither one needs the control-plane permission that `CreateDatabaseIfNotExistsAsync` requires.

1. Set the environment variable for your Azure Cosmos DB account and run the project:

    ```powershell
    $env:COSMOS_ENDPOINT = "https://<your-account>.documents.azure.com:443/"
    dotnet run
    ```

1. Verify the output shows the cloud account name and region.

1. Clear the variable to return to the emulator:

    ```powershell
    Remove-Item Env:COSMOS_ENDPOINT
    dotnet run
    ```

::: zone-end

::: zone pivot="python"

1. Replace the hardcoded emulator constants with environment variable lookups:

    ```python
    endpoint = os.environ.get("COSMOS_ENDPOINT", "https://localhost:8081/")
    emulator_key = "C2y6yDjf5/R+ob0N8A7Cgv30VRDJIWEHLM+4QDU5DE2nQ9nDuVTqobD4b8mGGyPMbIZnqyMsEcaGQy67XIw/Jw=="
    use_cloud = "COSMOS_ENDPOINT" in os.environ
    ```

1. Replace the client initialization line with:

    ```python
    if use_cloud:
        credential = DefaultAzureCredential()
        client = CosmosClient(url=endpoint, credential=credential)
    else:
        client = CosmosClient(url=endpoint, credential=emulator_key, connection_verify=False)
    ```

1. Replace the database and container creation from Task 3 so that it only runs against the emulator:

    ```python
    if use_cloud:
        database = client.get_database_client("cosmicworks")
        container = database.get_container_client("product")
    else:
        database = client.create_database_if_not_exists(id="cosmicworks")
        container = database.create_container_if_not_exists(
            id="product",
            partition_key=PartitionKey(path="/categoryId"),
            offer_throughput=400)

    print(f"Database:         {database.id}")
    print(f"Container:        {container.id}")
    ```

    `get_database_client` and `get_container_client` build client-side references without calling the service, so neither one needs the control-plane permission that `create_database_if_not_exists` requires.

1. Set the environment variable for your Azure Cosmos DB account and run the script:

    ```bash
    export COSMOS_ENDPOINT="https://<your-account>.documents.azure.com:443/"
    python app.py
    ```

1. Verify the output shows the cloud account name and consistency policy.

1. Clear the variable to return to the emulator:

    ```bash
    unset COSMOS_ENDPOINT
    python app.py
    ```

1. When you finish testing, deactivate the Python environment:

    ```bash
    deactivate
    ```

::: zone-end

## Clean up resources

When you finish the course, if you aren't planning to use the resources again, delete the resource group to stop all charges:

```azurecli
az group delete --name $resourceGroup --yes --no-wait
```

If your lab environment provided the resource group, delete only the Azure Cosmos DB account instead:

```azurecli
az cosmosdb delete --name <your-account-name> --resource-group $resourceGroup --yes
```
